# WAL（Write-Ahead Log）設計

## 概要

クラッシュ後のデータ復旧を保証するためのログ機構。**Redoのみ**を実装する。

---

## ポリシー

| ポリシー | 内容 |
|---------|------|
| **No-Steal** | コミット前のdirtyページはディスクに書かない |
| **No-Force** | コミット時にページをディスクに書くことを強制しない |

**No-Steal** により、ディスク上には常にコミット済みのデータしか存在しない。クラッシュ後に未コミットの変更を取り消す必要がないため、Undoが不要になる。

**No-Force** により、コミット時にページをディスクに書く必要がない。コミット済みでもページがディスクに反映されていない可能性があるため、クラッシュ後のRedoが必要になる。

---

## コミット時の処理

```
1. COMMITログレコードをログバッファに追加
2. ログバッファをディスクにフラッシュ  ← ここでコミット完了
3. ページはフラッシュしない（No-Force）
```

ログのCOMMITレコードがディスクに書けた時点でコミット完了とみなす。

---

## クラッシュ後の復旧

```
コミット前にクラッシュ:
  ログもページもメモリにある → 両方消える（No-Steal）
  ディスクは汚れていない → 何もしなくてよい

コミット後、ページ未反映でクラッシュ:
  ログはディスクにある → Redoで復旧
```

---

## ROLLBACK

No-Stealポリシーにより、未コミットのページはバッファプール上にしかない。ROLLBACKはdirtyページを破棄するだけでよい。

---

## 採用しなかった選択肢

| 項目 | 理由 |
|------|------|
| Undo | No-Stealポリシーにより不要 |
| Steal | UndoとセットになりWALが複雑になる |
| Force | コミットのたびにI/Oが増え、バッファプールの効果がなくなる |
