# ホーム画面UI設計

`sql-home-screen`(Figma)のレイアウト設計。バトル画面(`battle_screen_ui.md`)から見た目のトーン(ダーク×ターミナル/ネオン)を引き継ぎつつ、画面の構造はDuolingoのレッスンパスを参考にした。

- Figmaファイル: https://www.figma.com/design/SYNd796ebb3ETGhECYVlFc/ (`sql-home-screen`フレーム)
- ヘッダーはバトル画面のものをそのまま複製して流用(`SQL`バッジ + `SQL-MONSTER` + 三本線設定ボタン)。

---

## 画面構成

```
header-bar (バトル画面と共通)

path-section
  6体のモンスターノードを縦方向のジグザグ配置で並べる
  ノード間を線でつなぐ(攻略済み区間=実線シアン、未開放区間=点線グレー)
  現在挑戦可能なノードだけ大きく強調 + STARTボタン
```

### ノードの状態(3種)

| 状態 | 見た目 |
|---|---|
| CLEARED(攻略済み) | 難易度の色で塗りつぶし、通常サイズ(直径72px)、ネオングロー(ドロップシャドウ、不透明度55%) |
| CURRENT(挑戦可能) | 一回り大きく(直径96px)、白い枠線+強めのグロー(不透明度75%)、外側に二重のハローリングを追加、`START`ボタンを添える |
| LOCKED(未開放) | グレーアウト(直径72px、大型のボスノードのみ110px)、グローなし(あえてフラットにして目立たなくする) |

素の塗りつぶし円だけだと単調だったため、グロー・ハローリングを追加して現在地に視線が集まるようにした。

**あえてノードに文言(DONE/LOCKEDなど)は付けていない。** バトル画面の`turn-phases`で「状態は色だけで十分、文言は蛇足」という結論が出ていたため、ここでも色・サイズ・枠線だけで状態を表現する方針を踏襲した。

### 難易度の色分け

プロトタイプ段階として、レベルを2体単位で3バンドに分け、バトル画面の弱点表示などで使っている配色をそのまま再利用:

| レベル | 色 | 備考 |
|---|---|---|
| Lv1-2 | シアン | |
| Lv3-4 | オレンジ | |
| Lv5-6 | レッド | **Lv6のみボスとして扱う** |

**ロック中のノードもグレー一色ではなく、該当レベルの色を塗る。** タップして開くまでは詳細不明だが、色相だけでレベル帯が伝わるようにした。不透明度は当初35%にしたところ「現在地以外全部薄くて色の違いがわからない」というフィードバックがあり、60%まで引き上げて色相がはっきり見えるように調整した。

**Lv6(ボス)は円ではなく六角形にして、ロック中でも他ノードと明確にシルエットが違うようにした。** サイズも一回り大きい(126px)。

**クリア済み(Lv1-2)は不透明度75%、ネオングローなし。** 現在地ノードとの対比(グロー+ハローリング+フルの不透明度)は保ちつつ、不透明度を下げすぎて色相が埋もれないよう調整した。「現在地を目立たせる」役割はグロー・ハローリング・サイズが担い、不透明度は状態(クリア/ロック/現在地)の微妙な差をつける程度に留めている。

モンスターの絵をノード上に置く(将来対応): 現時点ではプレースホルダーの図形のみ。いずれ各ノードの上にモンスターの立ち絵/アイコンを重ねる想定(未着手)。

## 背景

`path-section`の中に、格子状のグリッド(48px間隔、シアン・不透明度6%)をノード・線の下に敷いた。データベースのスキーマ図/回路基板を思わせる意図で、視認性を邪魔しない程度に薄くしている。写真・イラスト系の背景(モンスターカードのようなAI生成画像)は今回のツールでは作れないため見送り、図形だけで組める案を採用した。

## 決定事項

- **ノードタップ時の挙動**: バトル画面へ直接遷移せず、まずモンスター情報の**プレビュー**を表示する。プレビューの中身は下記「プレビューモーダル」の通り確定済み。
- **モンスターの総数**: 現時点では6体(低2体・中2体・高2体)。今後増える前提で、パスは追加ノードを継ぎ足せる作りにしておく。

## プレビューモーダル(`monster-preview`)

ノードタップ時に表示するモーダル。パス上にあった`START`ボタンはここに統合し、パス側の単独ボタンは削除した(ノードタップ→プレビュー→`START BATTLE`、という導線に変更)。

構成(上から順):

- 閉じるボタン(`x`)
- モンスターのビジュアル(プレースホルダー枠。下記「プレースホルダー画像について」参照)
- モンスター名 + `BOSS`タグ(該当時) + `LVL`(バトル画面の`name-level`と共通のスタイルを流用)
- `MAX_HP`(基本ステータスのみ)
- `START BATTLE`ボタン

**弱点(WEAKNESS)は表示しない。** spec.mdの核心メカニクス(弱点はSQLで分析して見つけるものであり、事前に開示しない)を壊さないため、プレビューでは基本ステータスだけに留めている。

### プレースホルダー画像について【解決済み】

当初バトル画面の`monster-card`(AI生成のプレースホルダー画像)をそのまま複製して使ったが、その画像には`WEAKNESS: ACID / WATER`などのHUD風テキストが直接焼き込まれており、プレビューで弱点を事前に見せてしまう問題があった。

**方針転換: モンスター画像は「モンスターだけ」を写したものにする。** HUD情報(TARGET_ID・ARMOR_CLASS・WEAKNESSなど)は画像に焼き込まず、別の実テキストノードとして重ねる方針に統一。バトル画面側の`monster-card`の画像を実際にHUDテキストなしのものに差し替え済みで、プレビューもその同じ画像をそのまま複製して使っている。

## 未定事項・次回に持ち越し

- streak(連続日数)やジェムのようなリソース常時表示は今回スコープ外(ユーザー判断)。将来的に追加するかは未定。
- ノード同士をつなぐ線はFigma上ではVectorノードの直線パスで実装(単純な直線同士の接続。曲線ではない)。
- 現状「モンスターだけの画像」があるのはObsidian Golem(low〜mid想定の1体)のみ。残り5体分の素材はまだない。
