# WAL 仕様

## 概要

クラッシュ後のデータ復旧を保証するためのログ機構。Redoのみを実装する。

---

## ポリシー

| ポリシー | 内容 |
|---------|------|
| **No-Steal** | コミット前のdirtyページはディスクに書かない |
| **No-Force** | コミット時にページをディスクに書くことを強制しない |

No-Stealにより、ディスク上には常にコミット済みのデータしか存在しない。そのためUndoは不要。

No-Forceにより、コミット後もページがディスクに反映されていない可能性があるため、クラッシュ後のRedoが必要。

---

## コミット時の処理

```
1. COMMITログレコードをログバッファに追加
2. ログバッファをディスクにフラッシュ  ← ここでコミット完了
3. ページはフラッシュしない（No-Force）
```

---

## クラッシュ後の復旧

```
コミット前にクラッシュ:
  ログもページもメモリにある → 両方消える
  ディスクは汚れていない → 何もしなくてよい
  途中でログの書き込みが終了してしまったtxn(コミットログがない)は無視

コミット後、ページ未反映でクラッシュ:
  ログはディスクにある → Redoで復旧
```

---

## ログレコード

| Field | Size | Type | 説明 |
|-------|------|------|------|
| LSN | 8 | uint64 | ログシーケンス番号（通し番号） |
| TxnID | 8 | uint64 | トランザクションID |
| PageID | 4 | uint32 | 変更したページID |
| Operation | 1 | uint8 | 操作種別 |
| PrevLSN | 8 | uint64 | 同一トランザクションの前のLSN |
| RedoSize | 2 | uint16 | Redoデータのバイト数 |
| RedoData | 可変 | - | 変更後のデータ |

### Operation の種別

| 値 | 操作 |
|----|------|
| `0x01` | INSERT |
| `0x02` | UPDATE |
| `0x03` | DELETE |
| `0x04` | COMMIT |
| `0x05` | ABORT |

---

## LSN

ページヘッダに「最後に反映したLSN」を記録する。復旧時にログのLSNとページのLSNを比較して、どこからRedoすればよいかを特定する。

---

## チェックポイント

ログファイルが無限に増えないよう定期的にチェックポイントを取る。詳細は実装時に決定する。
